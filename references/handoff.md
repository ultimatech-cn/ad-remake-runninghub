# 取证与交付规范

## 从视频建立可复核证据

有本地视频、Python 3 和 FFmpeg 时，从安装后的 Skill 目录运行：

```bash
python3 scripts/probe_video.py "/path/to/reference.mp4" "/path/to/new-evidence-folder"
```

工具按画面变化给出硬切候选，每个区间尝试提取前、中、后三帧，另写出 `evidence.json`。候选阈值默认 0.30，可用 `--threshold` 调整；低阈值会增加候选。用 `--ffmpeg` 指定已有二进制的路径。输出目录须为新目录。时间是请求抽帧的时间，容器时长和抽帧时间用于定位。无候选、漏检、闪白误检或渐变时，用播放器或附加时间点补核。音轨标记只表示检测到流，声音内容须另行核对。工具不可用时用时间戳帧和用户描述完成现有证据支持的工作。

## 策划交付

- **需求和素材。** 商品名、已知卖点与依据、素材来源和权限状态、目标受众与目标行为（未知可标待定）。备注时长、比例和音轨的实际检查结果。
- **参考拆解。** 每行给时间段、证据帧、所见画面与声音、广告功能、迁移决策。把首个商品清晰露出、主要卖点证明和收尾分别定位。解释哪些节奏和构图值得保留，哪些内容需重拍或重写。
- **商品一致性。** 按优先级记录可见轮廓、颜色、部件位置、真实标识等。商品图只见正面时，避免把背面和内部作为核心镜头。把外观识别与功能宣称分别核对。
- **新片分镜。** 每行给预计时段、景别与动作、对应卖点或广告任务、文案或声音安排、所需资产。时段连贯，约 15 秒作为本应用策划基准。首镜尽早交代商品或明确钩子，收尾留出辨认时间，具体分配按参考和商品调整。

## 网页交接与版本记录

| 应用字段 | 核对 |
| --- | --- |
| 参考广告视频 | 上传视频文件。记录原版或裁剪版、清晰度、画幅与参考段落，帧图只用于分析。 |
| 商品图片 | 上传完整商品图。确认主体清晰、比例准确、关键部件可见，并记录所用图片版本。 |

用户运行后记录日期、输入文件名、任务标识和输出文件名。应用没有分镜或提示词字段，创意要求通过参考片选择、商品图和后期实现。实际费用以页面显示为准。

## 成片验收

| 检查项 | 记录方式 | 修正路径 |
| --- | --- | --- |
| 商品真实性 | 在首次清楚露出、运动峰值和结束帧查轮廓、部件、配色、标识。变形或误导性卖点需修正后再交付。 | 优先换更清晰、部件无遮挡的商品图。 |
| 广告表达 | 记录钩子、核心展示、结尾时间点，检查动作逻辑和裁切。 | 换结构更清楚的参考段，保留商品图。 |
| 文字与声音 | 检查生成文字、遮挡、错读、音轨和投放字幕需求。 | 在后期使用已核实的文案和标识。 |
| 镜头稳定性 | 标注闪烁、跳变、人物或手与商品接触异常的时间点。 | 检查问题是否集中于参考片的遮挡或快速动作，必要时换参考段。 |

每项填「通过／待改／待测」与时间点。两版用同一清单和同一类镜头并排比对；实际时长不同时，按开场、展示、结束三个叙事点对齐。仅有截图时，运动和音频保持待测。
